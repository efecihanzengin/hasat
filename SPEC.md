# SPEC.md — YouTube Bulk Transcript Extractor

## 0. Purpose

A tool that extracts transcripts from every video in a YouTube channel or
playlist and exports them as TXT, JSON, CSV, SRT, VTT or Markdown.

This spec covers **v0 only**. v1 is outlined at the end for context but is
explicitly out of scope. Do not build v1 features.

---

## 1. Critical architectural constraint (read this first)

Transcripts MUST be fetched from the user's own browser, not from a server.

YouTube blocks most datacenter/cloud IP ranges. A server-side fetcher will
return `RequestBlocked` / `IpBlocked` / HTTP 429 as soon as it is deployed,
regardless of request volume. Static residential and datacenter proxies are
detectable at ASN level. YouTube has also added a "proof of origin" token
(PoToken) requirement to parts of its bot-detection stack.

Therefore v0 is a **Chrome MV3 extension**. The content script runs on
`youtube.com`, so requests are same-origin, carry the user's session, and
originate from a residential IP. There is no backend, no proxy layer and no
network calls to any host other than `youtube.com` / `googlevideo.com`.

If a task seems to require a server, stop and ask. Do not introduce one.

## 2. Stack

- TypeScript, strict mode. No `any` in committed code.
- pnpm workspaces monorepo.
- `packages/core` — pure TS library. No DOM, no `chrome.*`, no `fetch` at
  module scope. Parsing and format conversion live here and are unit tested
  against fixtures.
- `apps/extension` — Chrome MV3 extension. Vite + CRXJS + React for the popup.
- Vitest for tests. ESLint + Prettier.

## 3. Data model

```ts
type Segment = {
  start: number;        // seconds, float
  duration: number;     // seconds, float
  text: string;         // decoded, entity-unescaped, whitespace-collapsed
};

type Transcript = {
  videoId: string;
  title: string;
  channelName: string;
  language: string;     // BCP-47, e.g. "en", "tr"
  isAutoGenerated: boolean;
  segments: Segment[];
};

type JobItem = {
  videoId: string;
  title: string;
  status: "pending" | "fetching" | "done" | "skipped" | "failed";
  error?: ExtractionError;
};
```

## 4. Extraction pipeline

### 4.1 Enumerate videos

Input is a channel URL (`/@handle`, `/@handle/videos`, `/channel/UC...`) or a
playlist URL (`/playlist?list=...`).

Enumeration uses YouTube's InnerTube `browse` endpoint. Read the API key and
client version from the page context (`ytcfg` / `INNERTUBE_API_KEY`,
`INNERTUBE_CLIENT_VERSION`) rather than hardcoding them — they rotate.

Results are paginated via continuation tokens. Follow continuations until
exhausted. A large channel can exceed 1000 videos; the enumerator must be a
generator/async-iterator that yields pages, not a function that buffers
everything before returning.

Hardcoding a response shape from a single observed payload is the most likely
failure here. Parse defensively: locate `videoRenderer` / `playlistVideoRenderer`
nodes by walking the object tree, not by fixed index paths.

### 4.2 Fetch one transcript

1. Call the InnerTube `player` endpoint for the videoId.
2. Read `captions.playerCaptionsTracklistRenderer.captionTracks`.
3. Track selection order: user-selected language → manually created track in
   the video's default language → auto-generated track → first available.
4. Fetch the track `baseUrl` with `&fmt=json3` appended. Parse `events[]` into
   `Segment[]`. Drop events with no `segs`. Concatenate `segs[].utf8`.
5. Normalize: unescape HTML entities, collapse runs of whitespace, trim,
   drop segments that are empty after normalization.

### 4.3 Concurrency and pacing

- Max 3 concurrent video fetches. Configurable, hard ceiling of 5.
- 250–500ms jittered delay between requests.
- On HTTP 429: exponential backoff (1s, 2s, 4s, 8s), max 4 retries, then mark
  the item `failed` and continue with the rest of the job. Never abort the
  whole job because of one video.

## 5. Error taxonomy

Every failure maps to exactly one of these. The UI shows the human message;
the export includes the code.

| Code | Cause | UI message |
|---|---|---|
| `NO_CAPTIONS` | Video has no caption track | "No transcript available" |
| `PRIVATE_OR_MEMBERS` | Private, members-only, or deleted | "Video not accessible" |
| `AGE_RESTRICTED` | Requires sign-in / age verification | "Age-restricted video" |
| `LIVE_STREAM` | Ongoing live stream | "Live stream — skipped" |
| `RATE_LIMITED` | 429 after all retries | "Rate limited, try again later" |
| `PARSE_ERROR` | Response shape unrecognised | "Could not parse response" |
| `UNKNOWN` | Anything else | "Unexpected error" |

`PARSE_ERROR` must log the raw response to the extension console for
debugging. It must never crash the job.

## 6. Export formats

All formatters are pure functions in `packages/core`:
`(t: Transcript, opts) => string`.

- **TXT** — plain text, no timestamps by default, paragraph breaks on gaps > 2s.
  Option: `includeTimestamps` prefixes `[mm:ss]`.
- **JSON** — the `Transcript` object, pretty-printed, 2-space indent.
- **CSV** — header row `start,duration,text`. RFC 4180 quoting: fields
  containing comma, quote or newline are quoted, inner quotes doubled.
- **SRT** — 1-based index, `HH:MM:SS,mmm --> HH:MM:SS,mmm`, blank line between
  cues. End time is `start + duration`, clamped so cues never overlap.
- **VTT** — `WEBVTT` header, same timing but with `.` as the ms separator.
- **Markdown** — `# {title}` heading, channel and language as a metadata block,
  then the TXT body.

Timestamp formatting is the highest-risk area for off-by-one bugs. It needs
dedicated unit tests covering: 0s, sub-second values, values crossing a minute
boundary, values crossing an hour boundary, and durations over 10 hours.

**Bulk export:** a single `.zip` containing one file per video, named
`{index}-{sanitized-title}-{videoId}.{ext}`. Sanitization strips characters
illegal on Windows (`< > : " / \ | ? *`), collapses whitespace to `-`, and
truncates to 100 characters while preserving the extension. Include a
`manifest.json` listing every item with its final status and error code.

## 7. UI

Two surfaces.

**Injected button** — appears on channel and playlist pages, next to the
existing YouTube controls. Label: "Transcribe". Must survive YouTube's SPA
navigation (YouTube does not do full page loads; use a MutationObserver or
`yt-navigate-finish` and re-inject on route change). Must not duplicate itself
on repeated navigation.

**Popup panel** — opened by the button. Shows:
- detected source (channel/playlist name, video count)
- format checkboxes, language selector, timestamp toggle
- Start button
- during a job: progress `{done}/{total}`, a scrolling list of items with
  status, and a Cancel button
- on completion: a Download button and a summary line
  (`412 exported, 18 skipped, 3 failed`)

Cancel must abort in-flight requests via `AbortController` and still offer a
download of whatever completed.

State lives in the service worker, not the popup — closing the popup must not
kill a running job.

## 8. Acceptance criteria

v0 is done when all of the following hold:

1. `pnpm typecheck && pnpm lint && pnpm test && pnpm build` passes clean.
2. Unit tests for all six formatters run against committed fixtures with zero
   network access, and cover the timestamp edge cases listed in §6.
3. A parser test suite runs against at least 3 committed raw InnerTube
   fixtures: a normal video, a video with no captions, and an auto-generated
   track with non-Latin script.
4. Loaded unpacked in Chrome, on a real playlist of ≥ 50 videos: the job
   completes, the zip downloads, the manifest matches the file list, and no
   uncaught exception appears in the service worker console.
5. A video without captions produces a `NO_CAPTIONS` entry in the manifest and
   does not interrupt the job.
6. Navigating between three different channels re-injects exactly one button
   each time.
7. `README.md` documents install-unpacked steps and the known limitations.

## 9. Out of scope for v0

Do not build, scaffold, or leave stubs for: accounts, authentication, credits,
payments, a backend API, an MCP server, a marketing site, analytics, or
Chrome Web Store packaging.

## 10. v1 outline (context only — do not implement)

A backend that offers the same extraction as an API for programmatic use.
This is where the real engineering cost sits: a job queue, workers, a rotating
residential proxy pool, response caching keyed by videoId + language, retry and
dead-letter handling, per-key rate limiting, credit accounting, and Stripe
webhooks. The extension stays free because the user's browser does the work;
the API costs money because the server has to buy its way past the IP blocks.

## 11. Legal note

YouTube's Terms of Service restrict downloading content. Personal use and
open-source publication are common in practice. Distributing this on the
Chrome Web Store or charging for it is a different risk posture and is the
owner's decision, not the agent's. Do not add branding that implies
affiliation with YouTube or Google.
